# 管理员后台需求与设计

## 1. 范围

首版管理员后台只解决两类运营需求：

1. 动态管理已经由部署环境配置好的文字模型：启用或停用、调用顺序、模型名和单供应商超时。
2. 查看最小必要账户数据，并对异常账户执行可恢复的暂停或恢复操作。

首版不在后台创建、展示或修改 API Key、Base URL、Supabase 密钥，也不读取密码、Access Token、题目、画布快照、图片或模型回答。账户永久删除继续走既有 7 天冷静期流程，管理员后台不提供绕过冷静期的删除按钮。

## 2. 管理员身份

- 管理员必须先是正常 Supabase 登录用户。
- 服务端通过 `ADMIN_USER_IDS` 环境变量中的 Supabase User UUID 白名单判定管理员身份。
- 前端路由和按钮只用于改善体验，所有 `/api/admin/*` 接口都必须重新验证 JWT 与服务端白名单。
- 管理员不能暂停自己的账户。
- 所有模型修改和账户暂停/恢复写入 `security_audit_events`，日志只保存 HMAC 摘要，不保存邮箱。

采用服务端 UUID 白名单而不是邮箱判断，避免邮箱修改、大小写和别名造成提权。首版不建设“管理员创建管理员”的界面，防止单个被盗管理会话继续扩散权限。

## 3. 模型动态配置

API Key、Provider 类型和 Base URL 继续由 Vercel 环境变量提供。后台只写入 Redis 的非敏感运行策略：

```json
{
  "providers": [
    { "id": "primary", "enabled": true, "model": "model-name", "timeoutMs": 12000 }
  ],
  "updatedAt": "2026-09-26T10:00:00.000Z",
  "updatedBy": "<user uuid>"
}
```

- Redis Key：`ai:admin:provider-policy:v1`。
- 至少保留一个已启用 Provider。
- Provider ID 必须来自部署环境的 `AI_PROVIDERS`，后台不能增加未知服务。
- 全链路超时仍不得超过 25 秒。
- Tutor 请求每次读取当前策略，因此保存后下一次请求生效，无需重新部署。
- Redis 或策略损坏时采用环境变量默认配置，不能把无效管理数据带入模型调用。

## 4. 账户数据

列表字段仅包括：用户 ID、脱敏邮箱、创建时间、最近登录时间、邮箱确认状态、暂停状态和画板数量。支持分页与当前页邮箱/ID搜索。

允许操作：

- 暂停账户：使用 Supabase Admin API 设置长期 ban；已签发会话的最终失效时间受 Supabase 会话/JWT策略影响。
- 恢复账户：清除 ban。

不允许操作：查看用户内容、修改密码、替用户确认邮箱、立即永久删除。

## 5. API

- `GET /api/admin/overview?page=1&search=`：返回管理员身份、模型策略、当前页账户和汇总数据。
- `PATCH /api/admin/models`：保存完整 Provider 顺序与启用状态。
- `PATCH /api/admin/accounts`：`{ userId, action: "suspend" | "restore" }`。

所有写接口要求允许的 Origin、Bearer JWT、JSON Content-Type，并返回统一错误契约。

## 6. 前端

- `/admin` 独立管理页，未登录引导登录，非管理员显示无权限。
- 顶部显示账户总量、已暂停数量、已启用模型数量。
- 模型卡片就地编辑，保存前校验至少启用一个 Provider 和总超时。
- 账户表格保持高信息密度，危险操作必须二次确认；不使用装饰性动画。
- 移动端改为卡片布局，所有操作保留明确文字标签。

## 7. 验收

- 非管理员和游客不能读取任何管理数据。
- API 响应和日志中不存在密钥、完整邮箱之外的额外身份信息、题目或画布内容。
- 管理策略保存后下一次 Tutor 请求使用新顺序、模型名和超时。
- 不能停用全部 Provider，不能暂停当前管理员。
- 暂停与恢复动作可追踪、可恢复且具有审计记录。
