# 03-28 Redis 原子额度与前端展示

## 本节点完成内容

- 将产品 AI 请求升级为 Redis Lua 原子预占：同时校验每日额度、首次使用起算的固定 30 天额度、5 分钟冷却和 `requestId` 幂等。
- 为插画建立独立的每日与固定 30 天额度，并提供原子预占、重复请求识别和失败返还；额度不足时返回 `vector_only`，不阻断文字与可编辑矢量图解。
- 游客额度为每日 3 次、30 天 15 次、每日 1 张插画、30 天 3 张；登录用户为每日 3 次、30 天 45 次、每日 2 张、30 天 20 张。
- 新增 `GET /api/ai/quota`，匿名会话和 Tutor 响应复用统一 `QuotaStatus` 契约，同时保留旧版顶层日额度字段。
- 画布桌面端与移动端显示今日 AI、30 天 AI、插画余额及 5 分钟倒计时；到达边界时在调用前阻止无效请求。
- 失败请求返还后若 30 天计数归零，会删除周期键，避免一次失败调用提前开启完整计费窗口。

## 验证范围

- 内存状态实现覆盖游客/用户差异、跨日累计、30 天窗口恢复、图片降级、幂等和失败返还。
- Redis 实现的 Lua 脚本保证并发请求不会通过“先读后写”绕过额度；真实 Upstash 并发仍需在 Preview 环境执行集成测试。
- 前端状态条遵循低干扰设计：数值更新不产生位移动画，只对边框和背景状态做短暂颜色过渡，并提供 `aria-live` 描述。
