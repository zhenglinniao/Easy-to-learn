# 阶段 3 / 节点 14：AI 反馈前端

## 状态

已完成。

## 交付范围

- 辅导板增加低视觉权重的“有帮助 / 有问题”入口；负向反馈必须从答案错误、解释不清、内容不合适和其他问题中选择。
- 前端 API 客户端接入 `POST /api/ai/feedback`，游客先建立匿名会话，登录用户携带 Bearer 凭据。
- 新生成辅导板持久化可选 `requestId`，用于关联服务端已完成请求；旧快照没有该字段时仍可恢复。
- 反馈入口仅在请求完成后的 24 小时窗口内显示，与服务端幂等缓存及身份校验保持一致。
- 发送中禁用重复提交；成功后显示确认状态，失败后保留重试入口。

## 隐私与需求边界

- 不增加自由文本、附件或原题上传，客户端只发送 `requestId`、评分和可选预定义分类。
- 不在画板快照中持久化反馈状态；`sending`、`sent` 和 `error` 都是当前页面的瞬时交互状态。
- 不改变已确认的每日 3 次 AI 配额和每 5 分钟一次限制；反馈请求不消耗 AI 配额。

## 设计工程说明

本节点使用 `emil-design-eng` 控制交互权重。反馈是高频辅助动作，不添加入场或展开动画；按钮只保留 120 ms 按压反馈、精细指针 hover 和清晰焦点环，`prefers-reduced-motion` 下移除缩放反馈。

## 验证

- Domain 测试覆盖旧快照兼容、合法 UUID 和非法 requestId。
- API 客户端测试覆盖登录反馈、游客会话与服务端错误。
- UI 测试覆盖正向评分、负向分类和成功确认状态。
- 全量质量门禁结果记录在 `docs/04-单元测试报告.md`。
