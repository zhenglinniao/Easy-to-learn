# 阶段 3 / 节点 6：画布与选区菜单

- 状态：已完成
- 日期：2026-09-22
- 范围：正式画布路由、选区触发规则、AI 输入准备、径向菜单与组件测试

## 完成内容

- 增加 `/canvas` 和 `/canvas/:boardId` 正式产品路由，继续以懒加载方式隔离 Excalidraw 大体积代码。
- 使用 Excalidraw 公共 imperative API 的 `onPointerDown`、`onPointerUp`、`getSceneElements`、`getAppState` 和 `getFiles`，未修改或 fork SDK 内部源码。
- 选区菜单严格限制为 selection 工具、鼠标输入、有效文字或视觉选区；触控、手写笔、普通拖动、空白点击和不支持元素不会触发。
- 支持点击选中与框选完成两种入口；重新选择、开始其他指针操作或改变选区时立即关闭菜单。
- 支持 text、freedraw、line、arrow、rectangle、ellipse、diamond 和 image 输入；文字按元素顺序拼接。
- 视觉选区以白色背景、20 px padding 导出 PNG；1.5 MiB 以内生成 Base64，较大图片保留 Blob 供下一节点走临时上传。
- 为 AI 来源生成稳定 SHA-256 内容摘要：只移动元素不会改变摘要，缩放或内容修改会改变摘要，从而支持后续 follow-source 与 stale 判定。
- 使用 Excalidraw 公共 `getCommonBounds` 生成 scene 坐标选区范围，并返回来源元素 ID、文字、图片和内容摘要。
- 新增可复用 `RadialMenu` 组件：中央 AI 标识、左右 Solve/Hint 动作、请求加载态、防重复提交、左右方向键/Home/End 导航和 Escape 关闭。
- 菜单位置在画布横向边界内收敛，保持 DOM overlay，不进入或修改 Excalidraw 元素层。
- UI 使用中文主标签并保留 Solve/Hint 英文语义；高频菜单不添加入场动画，只保留 120ms 按压反馈和受限 hover，`prefers-reduced-motion` 下移除位移动效。

## 测试覆盖

- 真实浏览器中完成“创建文字题目 -> 点击选区 -> 显示菜单 -> Solve 准备输入”流程。

## 设计工程取舍

本节点使用 `emil-design-eng` 检查交互密度和反馈。径向菜单属于每天可能使用数十次的高频动作，因此不增加入场或级联动画；按钮使用明确属性的短时 transition、细微按压缩放、指针能力限定的 hover 和清晰 focus ring。该取舍避免菜单阻碍连续选题，同时保留即时反馈。

## 边界

- 本节点只准备经过校验的 AI 输入，不调用模型、不消耗配额，也不生成占位答案。
