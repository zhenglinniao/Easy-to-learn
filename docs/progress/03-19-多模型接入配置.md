# 节点 03-19：多模型接入配置

## 目标

解除运行时对单一 Gemini API Key 的硬依赖，同时保持 Tutor DSL、安全边界、配额和前端契约不变。

## 实现

- `AI_PROVIDERS` 定义有序 Provider 链；每个标识通过 `AI_PROVIDER_<ID>_*` 独立配置。
- 原生支持 `gemini` 与 `openai-compatible` 两类适配器。后者覆盖 OpenAI、DeepSeek、通义千问、Moonshot、OpenRouter、Groq 和兼容 Chat Completions 的本地服务。
- Provider 仅在超时、网络失败或供应商错误时按顺序回退；业务校验失败仍执行原有一次 Tutor DSL 纠错，不把内容错误误判成基础设施故障。
- 两类适配器共用中文系统指令、模式提示、JSON 清理和可信元数据覆盖，模型不能伪造 model、prompt version 或生成时间。
- 支持 `json_schema`、`json_object`、`prompt` 三档结构化输出能力；由部署者根据所选供应商能力显式配置。
- Provider 链最多 3 个节点、累计超时不超过 25 秒；Vercel Tutor Function 时限为 60 秒，以容纳正常请求和至多一次格式纠错。
- 健康检查改为校验完整 Provider 配置，不再只检查 `GEMINI_API_KEY` 是否存在。
- 保留旧 `GEMINI_API_KEY`、`AI_MODEL`、`AI_TIMEOUT_MS` 配置兼容路径，避免已有部署立即中断。

## 安全边界

- 所有 API Key 只从服务端环境变量读取，不增加任何 `VITE_` 密钥。
- OpenAI-compatible 基础地址只接受 HTTP/HTTPS；Provider 标识、超时范围与响应格式均在启动路径校验。
- 错误响应不包含 API Key、请求正文、题图 Base64 或供应商原始响应体。
- 实际使用的 `provider/model` 写入 AI 元数据，便于审计和成本归因。

## 部署说明

最小单 Provider 配置示例：

```dotenv
AI_PROVIDERS=primary
AI_PROVIDER_PRIMARY_TYPE=openai-compatible
AI_PROVIDER_PRIMARY_BASE_URL=https://api.example.com/v1
AI_PROVIDER_PRIMARY_API_KEY=服务端密钥
AI_PROVIDER_PRIMARY_MODEL=支持图片的模型名
AI_PROVIDER_PRIMARY_RESPONSE_FORMAT=json_schema
```

真实供应商联调仍需要对应凭据；本节点只声明代码、契约和 fixture 测试完成，不宣称任何外部模型已经通过生产 E2E。
