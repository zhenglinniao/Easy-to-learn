# 阶段 3 / 节点 09：认证、多画板、导出与删除

## 交付范围

- 封装 Supabase Auth：Session 恢复、认证状态监听、邮箱密码登录/注册、Google/GitHub OAuth、登出和 PKCE callback 交换。
- redirect 只允许 `/`、`/boards`、`/canvas` 和合法画板路径；外部 URL、协议相对 URL、反斜线路径和未知路由统一回退 `/boards`。
- 实现远端多画板仓库：分页列表、创建、读取、重命名和硬删除；所有写操作使用既有 RPC，不传入或信任客户端 user ID。
- 实现标准 `.excalidraw` 与完整 `.easy-to-learn.json` 导出。Base64 只在用户主动导出的返回对象内生成，不写回快照或 IndexedDB；完整导出上限 100 MiB，缺失资产时整体失败。
- 实现账户删除申请与取消：要求有效登录，申请删除必须在最近 10 分钟内完成认证，固定 7 天冷静期，重复申请幂等，进入执行阶段后不可取消。
- 增加受 `CRON_SECRET` 保护的保留任务：认领到期删除请求、排队 Storage 对象清理、删除 Supabase Auth 用户、执行对象清理和既有保留期清理 RPC。
- 实现公开健康检查，仅返回版本、commit SHA 和依赖 `ok/degraded`，不探测付费 AI、不暴露配置值。

## 安全边界

- 浏览器只使用 Supabase anon key；service role 仅存在于服务端删除和保留任务。
- OAuth 由官方 SDK 的 PKCE 流程处理；应用不自行持久化明文令牌。
- 账户删除审计只记录不可逆 actor hash、事件类型、结果与 request ID，不包含画板内容、令牌或供应商正文。
- Storage 删除失败不会恢复已删除账户；任务最多重试 10 次并只保存稳定错误码。
- 画板删除没有回收站，UI 必须在节点 10 提供二次确认。

## 测试覆盖

- 安全 redirect 的允许和拒绝场景。
- 账户删除的最近认证、7 天冷静期、重复请求、取消和不可取消状态。
- 完整导出 Base64 隔离、Excalidraw 兼容结构与缺失资产失败。

## 基础设施阻塞

- 当前仍无 Supabase、Google/GitHub OAuth 和 Vercel Cron 的真实配置，因此真实 OAuth E2E、邮件投递、远端 CRUD、Auth 用户删除及定时任务执行不能宣称已验证。
- 代码、契约和 mock/纯逻辑测试可完成；真实供应商验证待凭据配置后单独执行并记录。
