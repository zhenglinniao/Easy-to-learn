# 阶段 3 / 节点 08：辅导板安全渲染与锚定

## 交付范围

- 实现 `TutorBoard`：标题、来源状态、步骤内容、前后导航、Explain step 入口、关闭与拖动。
- Hint 的 3 层内容由一次响应携带，初始只显示 `stepIndex = 0`，后续在本地逐级揭示，不产生新的 AI 配额请求。
- 实现 paragraph、math、list、callout、diagram 五类 Tutor DSL 渲染。
- KaTeX 固定使用 `strict: "error"`、`trust: false`，模型文字由 React 转义；不接收任意 HTML、原始 SVG、URL 或 `foreignObject`。
- 坐标、几何和流程图均由受控 React/SVG 元素生成。
- 实现来源关系计算：内容与尺寸不变的整体平移可跟随；内容、数量或尺寸变化为 `stale`；全部删除为 `orphaned`。
- 增加 `/spikes/tutor-board` 视觉验证页，不连接模型、不消耗配额。

## 交互与动效决策

本节点使用 `emil-design-eng` 约束高频交互，并用 `review-animations` 复核：

- 步骤切换和键盘操作不做入场动画，避免高频操作产生等待感。
- 按钮仅保留 120 ms 的按压反馈，hover 仅在精细指针设备启用。
- 拖动过程中直接写 GPU transform，不逐帧触发 React render；pointer up 时才提交持久化位置。
- `prefers-reduced-motion` 下移除按压位移动效。

动效审查结论：通过。未发现 `transition: all`、`scale(0)`、`ease-in`、布局属性动画、未受控 hover 或缺失 reduced-motion 等问题。

## 验证结果

- 组件测试覆盖：步骤切换、Explain step、关闭、拖动提交、HTML/可信链接拒绝。
- 适配器测试覆盖：整体移动跟随、内容/尺寸/数量变化 stale、全部删除 orphaned。
- 真实浏览器验证：响应式布局、KaTeX 公式、步骤切换与 ARIA 树正常；控制台无 error/warning。

## 已知边界

- 本节点只负责安全渲染与锚定交互；API 客户端编排、画板持久化接线在后续页面整合节点完成。
- `Explain step` 只暴露受控回调；其请求必须复用节点 07 的接口并携带父辅导板与目标步骤。
