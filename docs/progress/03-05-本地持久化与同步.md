# 阶段 3 / 节点 5：本地持久化与同步

- 状态：已完成
- 日期：2026-09-22
- 范围：IndexedDB、本地事务、资产落盘、outbox、同步状态机、跨标签页 writer 协调和 revision conflict copy

## 完成内容

- 新增独立 `@easy-to-learn/persistence` 包，只依赖领域协议和 `idb`，不耦合 React、画布 SDK 或 Supabase SDK。
- 建立 `easy-to-learn` version 1 数据库以及 `boards`、`assets`、`outbox`、`preferences`、`migrationBackups`、`conflictCopies` 六个 object store 和查询索引。
- durable change 在同一 IndexedDB 事务内更新画板并写入 outbox；同一画板只保留一个待同步 snapshot 任务。
- 删除任务会替换 snapshot 任务且不能被 snapshot 合并覆盖；迁移任务保持独立。
- 图片按 SHA-256、MIME、字节数和 `<ownerId>/<boardId>/<contentHash>` 路径校验，并要求先落盘，快照事务才可引用。
- 同步严格执行“上传缺失资产 -> 按 expected revision 提交快照”；单画板并发调用复用同一个执行 Promise。
- 网络或远端临时错误使用 1 秒起步、最长 5 分钟的指数退避；离线时不发出远端写入。
- 同步期间出现新本地修改时保留新 outbox，并把其 `baseRevision` 推进到刚成功的远端 revision，避免产生假冲突。
- revision conflict 立即停止该任务并保存包含完整本地快照的 conflict copy，不自动覆盖远端。
- IndexedDB 配额、损坏或迁移失败会转换为可操作的本地错误并阻断后续云写入。
- 提供包含六个 store 的原始本地备份导出，以及必须显式调用的安全数据库重置函数。
- 通过 `BroadcastChannel` 实现短租约 writer 选举；相同画板同时只由排序后胜出的标签页进入同步。
