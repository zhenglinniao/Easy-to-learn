# Easy to learn 访问与用户统计需求设计

状态：已评审，进入实现  
日期：2026-09-26

## 1. 目标与范围

在官网首页展示真实、可解释的产品使用规模，让访问者知道项目当前的使用情况，同时不给学习主流程增加干扰。

首版只展示以下三项聚合指标：

| 指标 | 展示名称 | 统计口径 |
| --- | --- | --- |
| 累计访问会话 | 累计访问 | 同一匿名浏览器连续 30 分钟内的页面访问合并为一次会话 |
| 近 30 天活跃访客 | 近 30 天访客 | 最近 30 个 UTC 自然日内出现过的去重匿名浏览器数量 |
| 注册账户数 | 注册学习者 | Supabase Auth 中当前存在的账户数量 |

本节点不包含：管理员明细后台、用户排行榜、实时在线人数、来源渠道分析、地域分析、设备指纹、第三方广告追踪以及收入指标。

## 2. 展示设计

- 统计区位于首页 Hero 与“为什么好用”之间，属于产品可信度信息，不抢占主行动按钮。
- 使用三列紧凑统计卡；窄屏自动降为两列和单列。
- 数据加载时保留稳定骨架，不让页面发生布局跳动。
- API 不可用时显示“暂未连接”，不以 `0` 冒充真实数据。
- 数值使用中文紧凑格式，例如 `1.2 万`；小规模阶段保留真实整数，不虚构增长。
- 统计值不使用滚动数字或循环动画。该信息高频出现，静态更新更清晰，并遵循 reduced motion。

## 3. 访问事件与去重

- 应用每次站内路由访问发送一次 `POST /api/analytics/visit`。
- 服务端签发一年有效、`HttpOnly + Secure + SameSite=Lax` 的随机访客 Cookie。
- 服务端使用密钥对随机 ID 做 HMAC；数据库只保存摘要，不保存原始 Cookie。
- 同一访客 30 分钟内的连续访问只增加页面访问量，不增加访问会话数。
- 浏览器启用 Do Not Track (`DNT=1`) 时不发送访问事件。
- 不保存页面正文、画布内容、邮箱、IP、完整 User-Agent、Referer 或查询参数。

## 4. 数据结构

### `analytics_daily_metrics`

每日聚合表：`day`、`page_views`、`visits`、`unique_visitors`。只包含不可关联到个人的计数，长期保留。

### `analytics_daily_visitors`

每日去重表：`day`、`visitor_hash`、`last_seen_at`。用于会话去重和近 30 天活跃访客计算，保留 90 天。

两张表强制 RLS，浏览器端无读写权限，仅 `service_role` 和受控数据库函数可以访问。

## 5. API

### `POST /api/analytics/visit`

- 入参：无业务正文。
- 出参：`204 No Content`。
- 安全：校验 `Origin`；Cookie 只在服务端处理；写入失败不阻断页面使用。

### `GET /api/analytics/metrics`

成功响应：

```json
{
  "data": {
    "totalVisits": 1280,
    "visitors30d": 430,
    "registeredUsers": 86,
    "cloudBoards": 214,
    "generatedAt": "2026-09-26T08:00:00.000Z"
  }
}
```

- 聚合结果允许 CDN/浏览器缓存 5 分钟。
- 所有计数均为非负整数；接口不返回用户或访客明细。
- 数据服务未配置时返回现有统一错误协议，前端显示不可用状态。

## 6. 数据保留与清理

- `analytics_daily_visitors` 保留 90 天，由现有保留任务清理。
- `analytics_daily_metrics` 为匿名聚合计数，长期保留。
- 删除账户不会影响已经匿名聚合的访问统计；账户数与画板数从当前数据库实时聚合，因此删除完成后会自动下降。

## 7. 测试与验收

- 数据库：RLS、授权、首次访问、30 分钟会话合并、跨会话累计、90 天清理。
- API：GET/POST 方法、Origin 校验、Cookie 属性、服务未配置、聚合返回结构。
- 前端：成功数据、加载状态、失败状态、数字格式和无障碍标签。
- 生产验收：首页访问不因统计失败而报错；生产 API 不泄露明细；桌面和窄屏布局均可读。

## 8. 风险与后续

- Cookie 被清除或更换浏览器会被视为新访客，这是非指纹统计的预期误差。
- 爬虫可能增加访问量；首版依靠 Origin 校验、会话合并和服务端摘要降低滥用，不宣称广告平台级精度。
- 若后续需要趋势图、来源分析或管理员钻取，必须单独评审采集范围、访问权限和保留期限。
