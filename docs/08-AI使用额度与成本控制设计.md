# AI 使用额度与成本控制设计

## 1. 目标与不变约束

Easy to learn 当前不设计付费套餐，因此额度系统的首要目标是：让真实用户能够完整体验“理解问题 -> 分步讲解 -> 手绘插画”，同时让任何单个用户、异常脚本或供应商故障都不能产生无限费用。

以下既有需求保持不变：

- 游客和登录用户每天最多发起 **3 次产品级 AI 请求**。
- 同一身份每 **5 分钟最多接受 1 次**新请求。
- 同一个 `requestId` 的刷新、轮询和幂等重试不重复扣次数。
- 一次正常的“解题/提示/解释”只扣 1 次产品请求；内部规划、校验和图片轮询不重复扣产品次数。

本设计增加月度封顶、独立生图额度、单次 Token 上限和全站预算熔断，不改变原有每日 3 次规则。

## 2. 免费期额度方案

### 2.1 产品请求额度

| 身份 | 每日上限 | 每 30 天上限 | 冷却时间 | 同时进行 |
| --- | ---: | ---: | ---: | ---: |
| 游客 | 3 次 | 15 次 | 5 分钟 | 1 个 |
| 登录用户 | 3 次 | 45 次 | 5 分钟 | 1 个 |

游客的 30 天额度以服务端签名的匿名会话为准。用户清理 Cookie 后可能获得新身份，因此它只能限制一般误用，不能承担全站成本保护；最终成本必须由全站预算熔断兜底。

### 2.2 生图额度

生图比文字推理昂贵且更容易产生并发堆积，必须单独计量。它不额外扣产品请求次数，但会扣“插画张数”。

| 身份 | 每日生成图上限 | 每 30 天上限 | 单次请求上限 |
| --- | ---: | ---: | ---: |
| 游客 | 1 张 | 3 张 | 1 张 |
| 登录用户 | 2 张 | 20 张 | 2 张 |

规则：

- 简单问题默认 0～1 张生成图，复杂问题最多 2 张，其余步骤使用 Tutor DSL 矢量图、公式、流程图和内置吉祥物。
- 图片理解不等于图片生成。用户上传一张题目图片仍只消耗 1 次产品请求，不扣生图张数。
- 规划模型建议生成 3 张以上时，策略层必须裁剪到额度允许的数量。
- 生图额度不足时不拒绝整道题，自动改成 `vector` 或 `hybrid`，保证文字、公式和结构图照常返回。
- 生图失败时返还对应插画额度；文字讲解已成功则不返还产品请求次数。

### 2.3 单次模型资源上限

以下是服务端硬限制，不允许客户端覆盖：

- 输入文字最多 10,000 字符；图片沿用现有文件大小、像素和 MIME 校验。
- 规划/完整讲解最大输出建议为 4,000 tokens；提示模式最大输出建议为 1,500 tokens。
- 最多进行 1 次结构纠错；供应商网络错误最多自动重试 1 次。
- 同一用户同时只能有 1 个文字任务和 1 个生图任务。
- 生图首版遵循商汤默认并发 1；没有购买额外并发前，不在应用层放大并发。

Token 限制是防止异常响应持续输出的保险丝，不作为用户可见的“次数”。如果内容因硬上限无法完整讲解，应缩短措辞和视觉数量，不允许静默截断关键答案。

## 3. 为什么采用“双额度”而不是统一积分

免费期不向用户展示复杂积分。用户只需要理解两件事：

1. 今天还能问几次；
2. 今天还能生成几张手绘插画。

内部仍分别记录请求数、输入/输出 tokens、生成图数量和估算成本。这样既保持交互简单，也避免“一道题生成多张图片”绕过每日请求限制。

按商汤当前公开价格，基础生图约为 0.03 元/张，高级生图约为 0.1 元/张；注册用户每 30 天最多 20 张，对应图片侧理论上限约为 0.6～2 元/人/月（不含文字模型）。价格是可变外部配置，不得写死在扣额逻辑中。官方价格页：<https://platform.sensenova.cn/product/APIService/pricing>。

## 4. 扣额顺序与状态机

```text
收到请求
  -> 校验身份、参数、画板权限和安全策略（不扣额）
  -> 原子预占 1 次产品请求
  -> 调用理解/规划模型
  -> 校验 Tutor DSL
  -> 按最终视觉计划原子预占 N 张插画
  -> 返回可立即展示的文字/矢量结果
  -> 异步生成插画并逐张结算
  -> settled | partial | refunded
```

关键规则：

- 先校验再预占，明显无效请求不扣额。
- 产品请求与插画额度分别预占，防止并发请求同时越过上限。
- `requestId` 是唯一结算键；同一键再次到达只能读取原结果或当前状态。
- 供应商 401、429、5xx、超时或网络失败：返还尚未成功的预占额度。
- 用户主动取消：尚未调用供应商时全部返还；供应商已完成的部分正常结算。
- 安全策略拒绝：若供应商调用前已拒绝，不扣额；供应商已完成安全判断则结算产品请求。
- Tutor DSL 无法通过一次纠错：返还产品请求，因为用户没有获得可用结果。
- 文字成功、图片失败：产品请求正常结算，失败图片额度返还并降级为矢量图。

## 5. 全站预算熔断

个人额度不能阻止大量匿名身份共同消耗成本，因此必须增加按北京时间自然日计算的全站预算。

首发建议配置：

```dotenv
AI_DAILY_COST_LIMIT_CNY=10
AI_COST_DEGRADE_PERCENT=85
AI_COST_STOP_PERCENT=100
AI_IMAGE_GLOBAL_DAILY_LIMIT=250
AI_IMAGE_GLOBAL_CONCURRENCY=1
```

处理策略：

- 达到预算 70%：仅告警，不影响用户。
- 达到预算 85%：关闭生成图，全部降级为矢量图；文字模型继续服务。
- 达到预算 100%：停止新的 AI 请求，已预占任务允许完成；返回明确的“今日公共额度已用完，明日恢复”。
- 图片总量上限和金额上限任一触发，都停止新生图。
- 供应商连续失败达到熔断阈值时，先切换已配置的文字后备模型；生图不跨供应商重做，直接降级为矢量图。

10 元/日只是小规模公测初始值，应通过环境变量调整。上线一周后依据真实日活、成功率和平均单次成本重新评估，不能用前端常量修改预算。

## 6. 数据结构

### 6.1 Redis 原子计数

所有预占和返还必须由 Lua 脚本一次完成，禁止“先读取剩余量再写入”。建议键：

```text
ai:action:day:{actorHash}:{yyyy-mm-dd}
ai:action:period:{actorHash}:{periodStart}
ai:image:day:{actorHash}:{yyyy-mm-dd}
ai:image:period:{actorHash}:{periodStart}
ai:rate:{actorHash}
ai:inflight:{actorHash}:{kind}
ai:reservation:{actorHash}:{requestId}
ai:global:cost:{yyyy-mm-dd}
ai:global:image:{yyyy-mm-dd}
```

`actorHash` 继续使用服务端 HMAC；Redis 不保存邮箱、原始用户 ID、IP、题目、提示词或图片内容。

“每 30 天”首版使用固定 30 天窗口，而不是自然月，避免月初集中刷新额度。Redis TTL 应覆盖窗口结束和 24 小时对账缓冲。

### 6.2 使用聚合表

新增 `ai_usage_daily`，仅用于成本分析与对账：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `usage_date` | date | 北京时间日期 |
| `actor_hash` | text | HMAC 后的用户/匿名身份 |
| `actor_type` | text | `guest` / `user` |
| `provider` / `model` | text | 供应商与模型 |
| `action_count` | int | 成功产品请求数 |
| `image_count` | int | 成功生成图数 |
| `input_tokens` / `output_tokens` | bigint | 供应商返回的 usage |
| `estimated_cost_micros` | bigint | 估算成本，避免浮点数 |
| `failed_count` | int | 失败调用数 |

只保留聚合元数据 90 天，与现有 AI 元数据策略一致。不得保存提示词、回答、画板内容、图片 URL 或用户邮箱。

## 7. API 契约

额度状态统一返回：

```json
{
  "action": {
    "dailyLimit": 3,
    "dailyRemaining": 2,
    "periodLimit": 45,
    "periodRemaining": 41,
    "nextAllowedAt": "2026-09-26T10:05:00.000Z",
    "dailyResetsAt": "2026-09-26T16:00:00.000Z"
  },
  "image": {
    "dailyLimit": 2,
    "dailyRemaining": 1,
    "periodLimit": 20,
    "periodRemaining": 18
  },
  "mode": "full"
}
```

`mode` 可为：

- `full`：文字与生成图都可用；
- `vector_only`：图片额度、全站图片预算或生图服务不可用；
- `paused`：全站总预算已触发停止线。

错误码：

| HTTP | code | 含义 |
| ---: | --- | --- |
| 429 | `RATE_LIMITED` | 5 分钟冷却未结束 |
| 429 | `DAILY_QUOTA_EXHAUSTED` | 当日 3 次已用完 |
| 429 | `PERIOD_QUOTA_EXHAUSTED` | 30 天产品请求额度已用完 |
| 503 | `GLOBAL_BUDGET_EXHAUSTED` | 全站公共预算已用完 |

图片额度不足不作为整份请求的错误，返回 `mode: vector_only` 和降级后的可用答案。

## 8. 前端交互

- 画布 AI 面板持续显示“今日 AI 2/3 · 插画 1/2”。
- 发起前显示“本次消耗 1 次 AI；最多生成 1 张插画”，复杂问题由规划后再更新为实际数量。
- 冷却期按钮禁用并显示准确倒计时，不让用户反复触发无效请求。
- 图片额度用完时文案为“今天的手绘插画额度已用完，本次改用可编辑图解”，不能伪装成系统错误。
- 30 天额度用完时显示恢复日期；公共预算用完时显示次日北京时间恢复。
- 首页公开访问量不能展示任何个人额度或成本明细。

## 9. 测试与验收

必须覆盖：

1. 游客和登录用户每日第 1～3 次成功，第 4 次拒绝。
2. 5 分钟边界、北京时间跨日、固定 30 天窗口边界。
3. 两个并发请求只有一个能够完成预占。
4. 相同 `requestId` 重试、轮询和刷新不重复扣额。
5. 规划成功但生图额度不足时自动矢量降级。
6. 文字失败全额返还；一张图片成功、一张失败时只结算成功图片。
7. 85% 预算进入 `vector_only`，100% 预算停止新请求。
8. Redis 暂时不可用时采用“拒绝新 AI、画板仍可编辑”的封闭失败策略，不能退回无限额度。
9. 日聚合的 tokens、图片数和估算成本能与供应商账单抽样对齐。
10. 日志、错误响应和分析表中不存在题目、邮箱、图片内容、API Key 和供应商临时 URL。

## 10. 实施顺序

1. 扩展 `QuotaStatus` 契约和前端额度展示，但保持兼容旧响应。
2. 将 Redis Lua 脚本升级为每日 + 30 天 + 并发预占，并补齐单元测试。
3. 在 SenseNova 生图任务接入时增加独立图片预占与逐张结算。
4. 接入 provider `usage`，建立价格配置与 90 天聚合记录。
5. 开启 10 元/日全站熔断，在开发环境验证 70%/85%/100% 三档行为。
6. 小流量上线一周，根据真实成本调整环境变量；不修改用户每天 3 次的产品承诺。
